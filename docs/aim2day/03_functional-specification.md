# Aim2Day 기능 명세서

## 1. 범위와 읽는 방법

이 문서는 [요구사항 명세서](01_requirements.md)의 **제출판 필수 기능**을 사용자의 조작과 시스템 동작으로 풀어 쓴다. 화면 이동은 [화면 흐름과 와이어프레임](02_user-flow-and-wireframes.md)을 따른다. HTML 시안의 예시 수치와 임시 저장 동작은 제품의 실제 데이터 규칙이 아니다.

- `필수`: 과제 제출판에서 구현·검증한다.
- `권장`: 일정이 허용하면 구현한다.
- `확장`: 제출판에는 개발 중 안내만 두고 실제 키 입력, 결제, AI 호출은 제공하지 않는다.
- 모든 조회와 변경은 로그인 사용자의 데이터에 한정한다. 삭제는 별도 표기가 없는 한 소프트 삭제다.
- 서버의 날짜 계산은 계정 시간대(기본 `Asia/Seoul`, 설정에서 변경 가능)와 설정된 주 시작 요일을 일관되게 사용한다. 저장 표현과 시간대 변경 시 기존 날짜 처리 방식은 API·데이터 설계에서 구체화한다.

## 2. 공통 규칙

### 2.1 목표 계층과 기간

`연간 목표 → 월간 목표 → 주간 목표 → 목표 연결 행동`의 한 경로를 유지한다. `그 밖의 할 일`은 목표 경로가 없는 별도 행동이다. 분기는 목표 단계가 아니라 리포트 기간이다.

| 단계 | 기간과 연결                                                                            | 화면 표시     |
| ---- | -------------------------------------------------------------------------------------- | ------------- |
| 연간 | 해당 달력연도 1월 1일~12월 31일. 같은 사용자·연도에 소프트 삭제되지 않은 목표 최대 3개 | `2026년`      |
| 월간 | 생성 당시 **현재 달**의 첫날~마지막 날. 연간 목표 하나에 연결                          | `2026.11`     |
| 주간 | 사용자의 주 시작 요일로 계산한 7일. 기간이 겹치는 월간 목표 하나에만 연결              | 시작일~종료일 |
| 행동 | 실제 수행일과 선택적 기한을 별도로 보유. 목표 연결 행동은 주간 목표 하나에 연결        | `2026.11.12`  |

월말·연말을 걸치는 주는 둘로 나누지 않는다. 주간 목표의 부모는 사용자가 선택한 월간 목표 하나다. 리포트의 행동은 그 목표가 속한 달이 아니라 **실제 수행일**의 월·분기·연도에 한 번 집계한다.

### 2.2 진행률의 의미

| 지표               | 계산                                                                                                              | 빈 상태·상한                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 체크형 주간 실행률 | 완료한 연결 행동 수 ÷ 연결 행동 수 × 100                                                                          | 연결 행동이 0개면 퍼센트 대신 `기록 없음`(표시 문구 제안)              |
| 수치형 주간 실행률 | 실제 완료값 ÷ 목표값 × 100                                                                                        | 목표값은 양수. 막대는 100%에서 멈추고 초과 실제값은 보존               |
| 월간 실행률        | 삭제되지 않은 모든 하위 주간 목표의 진행률을 가중 평균. 가중치 미지정 항목은 1, 기록 없는 항목은 0%로 분모에 포함 | 하위 목표가 0개면 `기록 없음`. 결과는 소수점 없이 반올림한 정수로 표시 |
| 연간 달성률        | **확정된** 달성 기준 중 달성한 기준의 배점 합계                                                                   | 기준·배점 합계 100점 확정 전에는 퍼센트 대신 `달성 기준 설정하기`      |

행동 완료만으로 연간 달성 기준이 자동 달성되지는 않는다. `그 밖의 할 일` 완료도 주·월·연간 진행률에 들어가지 않는다. 좌표 분류와 목록 정렬은 어떠한 진행률도 변경하지 않는다.

월간 실행률은 `각 주간 목표의 진행률 × 해당 가중치`의 합을 모든 하위 주간 목표 가중치의 합으로 나눈다. 예를 들어 100%(가중치 2)와 기록 없음(가중치 1)은 기록 없음 항목을 0%로 보아 `67%`로 표시한다. 표시값은 소수점 첫째 자리에서 반올림한다.

### 2.3 날짜와 API 오류

일정의 표시 날짜·마감일과 목표 행동의 실제 수행일은 서로 다른 정보다. 달력은 일정의 날짜를, 리포트는 행동의 실제 수행일을 사용한다. 마감일의 남은 일수는 계정 시간대의 달력 날짜로 비교한다. 마감일 당일은 `오늘`, 다음 날부터 `기한 지남`으로 표시한다.

모든 API 오류는 JSON의 `code`, 사용자가 읽을 수 있는 `message`, 필요한 경우의 `details`로 반환한다. 오류별 HTTP 상태 코드와 `details`의 세부 필드는 API 명세에서 확정한다.

### 2.4 삭제와 기록

목표 삭제 시 삭제 시각을 기록하고 그 목표와 하위 목표를 일반 조회·선택 목록에서 숨긴다. 그 경로의 **미완료** 행동도 오늘 목록에서 숨기되 복구 기간에는 연결 관계와 완료된 과거 기록을 보존한다. 삭제 시각부터 30일 동안 휴지통에서 복원할 수 있다. 하위 목표 자체가 별도로 삭제된 상태라면 상위 목표 복원만으로 해당 하위 목표를 복원하지 않는다. 연간 목표 복원은 최대 3개 제한을 다시 검사한다.

30일이 지나 복구 기간이 끝나면 해당 목표 경로의 앞으로의 계획과 미완료 행동을 영구 삭제한다. 완료한 목표·행동과 이미 달성한 기준은 당시 목표 이름·수행일 또는 완료일·달성 사실을 포함한 과거 이력으로 분리해 보존한다. 따라서 과거 리포트는 이 이력을 계속 집계하고, 해당 목표를 현재 계획이나 새 행동의 부모로 사용할 수 없다. 삭제 확인 화면과 휴지통에 만료일 및 이력 보존 범위를 알린다. 만료된 계획은 복원할 수 없다. 자동 정리가 지연되어도 만료된 계획의 복원 요청은 거부한다.

## 4. 제출판의 AI 진입점과 확장 경계

제출판의 AI 추천, AI 회고, BYOK 연결, 결제, 플러그인/MCP 진입점은 `해당 기능은 현재 개발 중입니다.`로 안내한다. API 키 입력 폼, 결제, 실제 AI 호출은 제출판 범위가 아니다. 기본 수동 기능과 기록 리포트는 AI 자격 없이 동작한다.

향후 확장판에서는 BYOK 또는 서비스 결제 자격을 **서버에서 요청마다 확인**한 뒤 목표 분해·배점·사분면 좌표·행동 관련성·회고 초안을 제시한다. AI 결과는 후보이며 사용자가 수정·일부 선택·승인하기 전에는 목표·행동·좌표·리포트를 저장하거나 삭제하지 않는다. 키 보관과 제공자 연결 방식은 별도 보안 설계가 필요하다. (AI-001~011, REVIEW-003)

## 5. 분산 서비스에서 확인할 동작

목표 서비스 동일 이미지 3개가 RR로 요청을 처리하고 동일 MySQL 데이터를 사용한다. 응답에는 처리 인스턴스를 검증할 식별자를 포함한다. 로그인 세션은 Redis로 공유해 다른 인스턴스로 요청이 전달되어도 같은 사용자 데이터가 보인다. MySQL 재생성 후 동일 영속 볼륨을 연결하면 목표 데이터가 유지된다. 이 항목은 사용자 기능과 별도로 과제 시연·검증 대상이다. (DIST-001~007)
