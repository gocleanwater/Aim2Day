# 프론트엔드 구현 계획

`frontend/`를 순수 HTML·CSS·JavaScript로 만든다. 빌드 도구·프레임워크·npm 의존성 없이 `nginx:alpine`이 정적 파일을 그대로 서빙한다. 화면 구조는 `docs/aim2day/02_user-flow-and-wireframes.md`, 시각 디자인·상호작용은 `design/aim2day-prototype.html`, 호출할 API와 응답은 `docs/aim2day/05_api-specification.md`(§5 화면별 호출 API 포함)를 따른다.

## 공통 결정(2026-11-18 밤, 사용자 수면 중 Claude가 정한 임시 결정 — 사용자 확인 대기, `docs/progress.md` "밤사이 미룬 결정")

- **한 페이지 앱 + 해시 라우팅**: `index.html` 하나에서 `#/login`, `#/dashboard`처럼 화면을 바꾼다. 시안이 한 파일 안에서 화면을 전환하는 구조라 그대로 옮기기 쉽고, Nginx에 SPA fallback 설정이 필요 없다. 비밀번호 재설정 링크는 이미 `#token=` 형식이다(API 결정 14).
- **파일 구조**: `index.html`, `css/app.css`(시안 스타일을 옮김), `js/api.js`(fetch 래퍼), `js/router.js`, `js/ui.js`(토스트·모달·공통 렌더 도우미), `js/views/<화면>.js`. ES 모듈(`<script type="module">`)로 나눈다. 빌드 단계는 없다.
- **시안의 시각 디자인을 그대로 쓴다.** 시안의 예시 데이터·localStorage 상태는 쓰지 않고 실제 API 값으로 채운다(CLAUDE.md: 시안의 예시 데이터를 DB 구조로 가정하지 않는다).
- **Dockerfile**: `COPY . /usr/share/nginx/html/`로 폴더 전체를 복사한다(Dockerfile 자체는 제외되도록 `.dockerignore`).

## API 호출 공통 규칙(`js/api.js`)

- 같은 출처(프록시 80)로 `fetch`하고 `credentials: 'same-origin'`.
- 상태 변경 요청(POST·PUT·PATCH·DELETE)은 `XSRF-TOKEN` 쿠키 값을 `X-XSRF-TOKEN` 헤더로 보낸다. 쿠키가 없으면 먼저 `GET /api/auth/csrf`를 부른다(공유 계약 §4).
- 응답 본문 `{code, message, data, details}`(API §2.1)를 풀어 성공이면 `data`, 실패면 `ApiError{status, code, message, details}`를 던진다.
- 401 `UNAUTHENTICATED` → 로그인 화면으로(돌아올 해시 기억). 403 `CSRF_TOKEN_INVALID` → csrf 재발급 후 한 번 재시도.
- 409 `VERSION_CONFLICT` → "다른 곳에서 먼저 수정됐어요" 안내 후 최신 값을 다시 불러온다(API §2.4).
- 400 `VALIDATION_FAILED`의 `details.fieldErrors`는 해당 입력칸 아래에 표시한다.
- 응답 헤더 `X-Instance-Id`를 화면 구석(설정 또는 바닥글)에 작게 표시해 RR 분산을 시연할 수 있게 한다(API §2.6, §5 끝 문단).

## 검증(오케스트레이터)

- 각 단위: `node --check`로 모든 JS 문법 확인.
- 화면 E2E: 서버 시험 환경(aim2day_review DB, 시험용 Redis, review 컨테이너)에 **시험용 프록시**(호스트 포트 8081, 운영 프록시와 같은 경로 규칙, 업로드한 frontend 폴더 서빙)를 띄우고, 로컬에서 Playwright(헤드리스 Chromium)로 실제 화면을 조작한다. 인증번호는 review user-service 로그에서 읽는다. 스크립트는 `tools/e2e/web/`.
- Codex 리뷰: 단위마다 1회 이상(원격·밤사이에는 Claude가 실행).
- 배포: 커밋 뒤 서버에서 `git pull` → `aim2day-frontend` 이미지 재빌드·재실행(07 문서 명령).
