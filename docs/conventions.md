# 문서 및 커밋 규칙

## Markdown 파일명

Markdown 파일명은 영어 소문자 kebab-case로 작성합니다. 기존 문서의 `01_` 같은 번호 접두사는 유지해도 됩니다.

예: `01_user-flow.md`, `project-grading-criteria.md`

## 커밋 메시지

커밋 메시지는 `타입: 작업 내용 (#이슈번호)` 형식을 사용합니다. 문서 변경에는 `docs` 타입을 사용합니다.

| 타입 | 설명 |
|---|---|
| feat | 새로운 기능 |
| fix | 버그 수정 |
| refactor | 코드 리팩토링 |
| docs | 문서 수정 |
| test | 테스트 코드 |
| chore | 빌드, 설정 변경 |

예시:

- `feat: 오늘의 할 일 목록 조회 API 추가 (#12)`
- `fix: 투두 완료 처리 날짜 오류 수정 (#34)`

이슈가 없는 작업은 번호를 만들지 않습니다.

## 커밋 전 확인

커밋 전에 변경할 관련 파일과 변경 내용을 확인합니다.
