# 클라우드 네이티브 프로젝트 채점 기준

- 원문: <https://hull.kr/cloud_native/23>
- 게시일: 2025-11-05
- 확인일: 2026-11-09
- 과제명: 기말고사(정규과제 포함) 대체 과제

> 원문에는 평가 항목별 배점이나 점수 비율이 공개되어 있지 않다. 아래 내용은 원문에 명시된 평가 항목, 필수 제출 자료, 감점 조건을 정리한 것이다.

## 1. 평가 항목

### 1.1 문서의 구성

- 문서 구성과 표현이 체계적인가?
- 정성과 완성도가 있는가?
- 다음 요소를 충실하게 포함했는가?
  - 전체 시스템 구성도
  - 통신 절차 또는 플로우 차트
  - 프로그램 설명
  - 설치 가이드
- 위 문서 구성 요소 전체를 기준으로 상대 평가한다.

### 1.2 프로그램의 창의성 및 완성도

- 프로그램 아이디어가 참신한가?
- 소스 코드의 네이밍이 적절한가?
- 코드에 주석이 충분하고 상세한가?
- 프로그램이 실제로 완성되었는가?
- 구현 공정률이 어느 정도인가?

### 1.3 도커 시스템 구성의 유효성

- 시스템 구성이 적절한가?
- 컨테이너 사이의 연결 관계가 적절한가?
- 컨테이너, 네트워크 등 시스템 구성 요소의 네이밍이 적절한가?
- 역방향 프록시, DB, 프론트엔드, 서버 프로그램 2개 이상, 세션 공유 서버를 포함해 **6개 이상의 컨테이너**로 구성했는가?
- 컨테이너 간 세션 공유와 마이크로서비스 구조가 실제로 동작하는가?
- 서로 다른 종류의 서버 시스템으로 마이크로서비스를 구성한 경우 가점 대상이 될 수 있다.

### 1.4 구현 검증 자료

구현 검증 자료는 보고서와 별도로 반드시 첨부해야 한다.

- 제출자가 직접 구현했다는 사실을 증명할 수 있어야 한다.
- 컨테이너 이름, 네트워크 이름, 포트 번호가 시스템 구성도와 실제 실행 화면에서 일치해야 한다.
- 다음 자료를 제출해야 한다.
  - 컨테이너 생성 명령어 전체
  - `docker ps` 실행 화면
  - `docker network inspect` 실행 화면
  - `docker exec -it 컨테이너명 bash` 실행 화면
  - 서버 간 세션 공유 검증 화면
  - DB 볼륨 마운트 및 데이터 영속성 검증 화면

## 2. 필수 구현 조건

- 자유 주제의 간단한 웹 프로그램을 개발한다.
- 역방향 프록시 컨테이너를 구성한다.
- DB 컨테이너를 구성한다.
  - 예: MySQL, MariaDB, Oracle, MongoDB, SQLite 등
- 프론트엔드 컨테이너를 구성한다.
  - HTML, JavaScript, jQuery 등 순수 JavaScript 계열만 사용할 수 있다.
  - React, Vue 등 빌드형 프론트엔드는 사용할 수 없다.
  - 핵심 코드에 상세한 주석을 작성한다.
- 서버 프로그램 컨테이너를 2개 이상으로 분할한다.
  - 예: PHP, Spring Boot, Node.js Express, Flask, Django, FastAPI 등
  - 핵심 코드에 상세한 주석을 작성한다.
- 세션 공유 컨테이너를 구성한다.
  - 사용자 기반 서비스여야 한다.
  - 여러 서버 사이에서 세션이 공유되어야 한다.
- 도커 이미지를 개인 Docker Hub에 업로드한다.
  - Mac에서도 ARM이 아닌 `amd64` CPU용 이미지로 빌드한다.
- Docker Compose는 사용하지 않는다.

## 3. 보고서 필수 내용

- 전체 시스템 구성도와 통신 절차
- 프로그램 소개
- 소스 코드와 구현 화면 캡처
- 실행에 사용한 모든 `docker build`, `docker run` 명령어를 실행 순서대로 기재
- Docker Hub 접속 정보
  - 아이디
  - 저장소 이름
  - 태그
- 설치 및 실행 방법

## 4. 시스템 구성도 작성 기준

- 반드시 본인이 직접 작성한다.
  - 손 그림 후에, PPTX, UML 도구를 이용해 그리고 제출한다.
- 그림 내부에 학번과 이름을 텍스트 요소로 포함한다.
- 생성형 AI로 구성도를 그리면 감점된다.
- 손 그림이 아니라면 원본 편집 파일을 함께 제출한다.
- Excalidraw를 사용한 경우 `.excalidraw` 원본 파일을 제출한다.

## 5. 시연 영상 필수 조건

- 3분 이내의 무편집 화면 녹화 영상을 별첨한다.
- 영상을 Google Cloud에 업로드하고 주소를 제출한다.
- 영상에서 다음 과정을 확인할 수 있어야 한다.
  1. 보고서에 적은 `docker run` 명령어를 같은 순서로 직접 실행한다.
  2. `docker ps`로 6개 이상의 컨테이너가 동작 중임을 확인한다.
  3. 브라우저에서 프론트엔드에 접속해 로그인한다.
  4. 다른 서버 컨테이너를 경유하는 요청에서도 세션이 유지됨을 확인한다.
  5. 컨테이너 재시작 후에도 DB 데이터가 유지됨을 확인한다.
- 컷 편집이나 화면 전환 효과를 사용하면 감점된다.
- 영상에서 실행하는 컨테이너 명령어는 보고서에 기재한 명령어와 같아야 한다.

## 6. 명시된 감점 위험

- 생성형 AI로 시스템 구성도를 작성한 경우
- 시연 영상에 컷 편집 또는 화면 전환 효과 등 편집 흔적이 있는 경우
- 편집 가능한 보고서 원본 없이 PDF 파일만 제출한 경우

## 7. 제출 전 최종 체크리스트

- [ ] 컨테이너가 총 6개 이상이다.
- [ ] 역방향 프록시 컨테이너가 있다.
- [ ] DB 컨테이너와 볼륨 마운트가 있다.
- [ ] 순수 JavaScript 계열의 프론트엔드 컨테이너가 있다.
- [ ] 서버 프로그램이 2개 이상의 컨테이너로 분리되어 있다.
- [ ] 별도의 세션 공유 컨테이너가 있다.
- [ ] 다른 서버를 경유해도 로그인 세션이 유지된다.
- [ ] 컨테이너 재시작 후에도 DB 데이터가 유지된다.
- [ ] 핵심 코드에 상세한 주석이 있다.
- [ ] 컨테이너·네트워크·포트 이름이 구성도, 명령어, 실행 화면에서 일치한다.
- [ ] 모든 `docker build` 및 `docker run` 명령어가 실행 순서대로 보고서에 있다.
- [ ] Docker Hub에 `amd64` 이미지가 업로드되어 있다.
- [ ] Docker Compose를 사용하지 않았다.
- [ ] 본인이 작성한 시스템 구성도에 학번과 이름이 들어 있다.
- [ ] 구성도 원본 편집 파일을 준비했다.
- [ ] 필수 명령어와 검증 화면을 모두 첨부했다.
- [ ] 3분 이내의 무편집 시연 영상과 공유 주소를 준비했다.
- [ ] 한글 또는 Word 등 편집 가능한 보고서 원본을 제출한다.
